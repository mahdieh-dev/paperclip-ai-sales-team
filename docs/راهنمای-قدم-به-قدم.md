# شروع کنیم

در این راهنما یک تیم چهار نفره می‌سازی که به‌جای چت‌های جداگانه، داخل **Paperclip** با هم کار می‌کنند. مدیر تیم وظیفه‌ها را تقسیم می‌کند؛ تحلیلگر مکالمه‌ها را بررسی می‌کند؛ کارشناس فروش پیشنهاد می‌دهد و نفر چهارم خروجی را کنترل می‌کند.

**تمرین ما:** یک فروشگاه فرضی با ۱۵ گفت‌وگوی مشتری. قرار است سه الگوی پرتکرار، پنج پاسخ پیشنهادی و سه ایده برای بهتر شدن مسیر فروش آماده کنیم. همه اطلاعات تمرین ساختگی‌اند.

## نقشه تیم

```text
                 صاحب کسب‌وکار
                       |
              Sales Manager (CEO)
                       |
        +--------------+--------------+
        |              |              |
  Customer Insight  Sales Response  Quality Reviewer
      Analyst         Strategist
```

## قبل از نصب چه چیزهایی لازم داری؟

- **کامپیوتر** با Windows، macOS یا Linux. این روش مخصوص نصب روی کامپیوتر است.
- **اینترنت** و امکان اجرای چند فرمان در Terminal.
- **Node.js نسخه 24.11 یا جدیدتر**، **pnpm**، **Python 3** و **Codex CLI**.
- حسابی که اجازه استفاده از Codex را دارد؛ می‌توانی از ورود اشتراکی ChatGPT استفاده کنی، اگر برای حسابت فعال باشد. محدودیت مصرف حساب همچنان برقرار است.

**روش استفاده از این فایل:** هر گام را انجام بده و «باید چه ببینی؟» را چک کن. تا وقتی نتیجه همان گام درست نشده، به گام بعدی نرو.

# بخش اول: نصب Paperclip

## گام ۱ — محیط اجرا را آماده کن

**اگر ویندوز داری:** از Start برنامه PowerShell را باز کن و برای نصب Ubuntu داخل WSL این فرمان را اجرا کن:

```powershell
wsl --install -d Ubuntu
```

اگر از تو خواست سیستم را ری‌استارت کنی، انجامش بده. Ubuntu را باز کن و برای خودت نام کاربری و رمز بساز. **ادامه فرمان‌های این راهنما را در پنجره Ubuntu اجرا کن، نه PowerShell.** اگر Ubuntu از قبل روی سیستمت نصب بوده، نیازی به نصب دوباره نیست.

**اگر macOS یا Linux داری:** برنامه Terminal خود سیستم را باز کن.

**باید چه ببینی؟** یک ترمینال باز داری که می‌توانی داخلش فرمان تایپ کنی. Codex و Paperclip باید داخل *همین محیط* نصب شوند.

## گام ۲ — Node.js و ابزارهای لازم را نصب کن

این فرمان را بزن:

```bash
node --version
```

اگر نسخه پایین‌تر از `v24.11.0` بود یا فرمان شناخته نشد، Node.js نسخه ۲۴ یا جدیدتر را در همان محیط نصب کن. برای نصب از نشانی رسمی `nodejs.org` استفاده کن. کاربران Ubuntu/WSL می‌توانند از راهنمای نصب Node.js برای Linux در سایت رسمی کمک بگیرند.

بعد این فرمان‌ها را یکی‌یکی اجرا کن:

```bash
npm install -g corepack
corepack enable
corepack prepare pnpm@latest --activate
python3 --version
node --version
pnpm --version
```

اگر `python3` موجود نبود، در Ubuntu با این فرمان نصبش کن:

```bash
sudo apt update && sudo apt install -y python3
```

**باید چه ببینی؟** فرمان‌های `node`، `pnpm` و `python3` نسخه نشان بدهند؛ Node حداقل ۲۴٫۱۱ باشد.

## گام ۳ — Codex را به حساب خودت وصل کن

```bash
npm install -g @openai/codex
codex login
```

صفحه ورود یا دستورالعملی را که Codex نمایش می‌دهد دنبال کن و وارد حساب خودت شو. برای اطمینان فرمان `codex` را اجرا کن و یک سؤال ساده بپرس.

**باید چه ببینی؟** Codex باز شود و پاسخ بدهد. اگر با خطای محدودیت مصرف یا دسترسی به مدل روبه‌رو شدی، اول همان را برطرف کن. لازم نیست کلید API را داخل این فایل یا چت بفرستی.

## گام ۴ — Paperclip را اجرا کن

در همان ترمینال:

```bash
npx paperclipai@latest onboard --yes
```

در پایان، نشانی زیر را در مرورگر باز کن:

```text
http://localhost:3100
```

**باید چه ببینی؟** صفحه شروع Paperclip. تا وقتی با برنامه کار می‌کنی ترمینال اجرای Paperclip را باز نگه دار. برای اجرای دوباره پس از بستن برنامه:

```bash
npx paperclipai run
```

**یادت باشد:** دستور نصب را با `sudo` یا حساب Administrator اجرا نکن. فعلاً نیازی به سرور و دامنه نیست.

# بخش دوم: شرکت و تیم را بساز

## گام ۵ — یک Company بساز

در راه‌انداز اولیه Paperclip یک Company بساز. این نام‌ها صرفاً برای تمرین‌اند:

- **نام شرکت:** `Sales Insight Lab`
- **هدف:** تحلیل مکالمه‌های مشتری، پیدا کردن سؤال‌ها و نگرانی‌های مشترک و پیشنهاد راهکارهای قابل آزمایش برای بهتر شدن فروش.

اگر Paperclip مستقیماً از تو خواست اولین Agent را بسازی، به گام بعدی برو.

**باید چه ببینی؟** اسم شرکت در داشبورد ثبت شده و می‌توانی صفحه Agents را باز کنی.

## گام ۶ — مدیر تیمت (CEO) را اضافه کن

در قسمت **Agents** گزینه ساخت ایجنت جدید را انتخاب کن و این اطلاعات را وارد کن:

| فیلد | مقدار |
|---|---|
| Name | `Sales Manager` |
| Role | `CEO` |
| Adapter | `Codex / codex_local` |
| Working directory | یک پوشه جدا مانند `~/paperclip-sales-lab` |

اگر برنامه از تو خواست اتصال مدل را مشخص کنی، از **ورود Codex مرحله ۳** استفاده کن. مدل را روی گزینه پیش‌فرضِ سازگار با حسابت نگه دار و **Test / Run test** را اجرا کن.

**باید چه ببینی؟** تست اتصال موفق باشد و Sales Manager در لیست Agents دیده شود.

## گام ۷ — شرح وظیفه مدیرعامل را وارد کن

یک مدیر AI فقط با اسم CEO مدیر نمی‌شود؛ باید بداند چطور کار تقسیم کند.

متن **پرامپت ۱: مدیرعامل** در پیوست همین PDF را در قسمت Instructions ایجنت قرار بده. اگر Paperclip به‌جای متن مستقیم، *مسیر فایل* می‌خواهد، از فایل `prompts/01-ceo.md` بسته همراه استفاده کن و مسیرش را وارد کن.

از مدیر بپرس: «قرار است چه کاری انجام بدهی و چه چیزهایی نیاز به اجازه من دارند؟»

**باید چه ببینی؟** توضیح بدهد که کارها را تقسیم می‌کند، گزارش مستند می‌خواهد و بدون اجازه تو به مشتری پیام نمی‌دهد.

## گام ۸ — سه کارمند متخصص را استخدام کن

در **Agents → New Agent** سه ایجنت جدید بساز. هر سه باید به `Sales Manager` گزارش بدهند (`Reports To`). برای هر کدام **Codex** را انتخاب کن، اتصال را تست کن و پرامپت مربوط را در Instructions بگذار.

| نام ایجنت | وظیفه | دستور آماده |
|---|---|---|
| `Customer Insight Analyst` | پیدا کردن الگو در مکالمه‌ها | پرامپت ۲ |
| `Sales Response Strategist` | نوشتن پاسخ و ایده آزمایشی فروش | پرامپت ۳ |
| `Quality Reviewer` | بررسی صحت خروجی‌ها | پرامپت ۴ |

**راه جایگزین:** می‌توانی «پرامپت ۵: استخدام تیم» را به مدیر بدهی تا خودش درخواست استخدام ثبت کند؛ هر درخواست را در Approvals بررسی و تأیید کن. برای اولین بار، **ساخت دستی** ساده‌تر و قابل کنترل‌تر است.

**باید چه ببینی؟** در Agents چهار نقش وجود داشته باشد؛ CEO بالای سه متخصص باشد و تست هر چهار اتصال موفق باشد.

## گام ۹ — بودجه و اجازه‌ها را مشخص کن

- اگر قسمت **Budget** وجود دارد، برای تست یک سقف کوچک انتخاب کن. مراقب باش این سقف لزوماً همان محدودیت اشتراک Codex نیست.
- اگر درخواست‌های **Approval** نمایش داده می‌شوند، استخدام یا تغییرات مهم را دستی تأیید کن.
- برای تست اول، **Heartbeat** زمان‌بندی‌شده را خاموش نگه دار تا ایجنت‌ها بی‌دلیل اجرا نشوند.
- دسترسی هر ایجنت را به فایل‌های تمرین محدود کن؛ به اینستاگرام، ایمیل یا حساب فروشگاه متصلش نکن.
- تنظیمات اجرای بدون sandbox/approval را فعال نکن.

**باید چه ببینی؟** تیم آماده است، اما بدون فرمان تو قرار نیست با مشتری تماس بگیرد یا تغییری در کسب‌وکار انجام بدهد.

# بخش سوم: اولین مأموریت را اجرا کن

## گام ۱۰ — فایل‌های تمرین را آماده کن

در انتهای این PDF، **اطلاعات فروشگاه نمونه** و **۱۵ مکالمه آزمایشی** آمده است. اگر بسته ZIP را داری، همین اطلاعات در دو فایل مجزا هم قرار دارند:

- `sample-data/business-facts.md` — اطلاعات محصول و محدودیت‌ها
- `sample-data/sample-conversations.csv` — ۱۵ مکالمه ساختگی

اگر فقط PDF را داری، می‌توانی صفحات پیوست داده‌ها را به ChatGPT بدهی و بخواهی CSV و فایل اطلاعات محصول را برایت بسازد. بعد فایل‌ها را خودت بررسی کن.

**باید چه ببینی؟** دو فایل تمرین را داری و می‌توانی آن‌ها را باز کنی.

## گام ۱۱ — پروژه و اولین Task را بساز

در **Projects** یک پروژه با نام `Sales Conversation Review` بساز. سپس یک Task به نام `Analyze 15 customer conversations` ایجاد کن.

- **Assignee / مسئول:** `Sales Manager`
- **Attachments:** دو فایل گام ۱۰
- **Description:** متن «پرامپت ۶: مأموریت اول» از پیوست PDF

**باید چه ببینی؟** تسک زیر نظر پروژه ذخیره شده و دو فایل همراهش دیده می‌شوند.

## گام ۱۲ — اول دسترسی به فایل‌ها را تست کن

قبل از اینکه تیم وارد تحلیل شود، این پیام را به CEO بده:

> فقط نام فایل‌ها، تعداد مکالمه‌ها و شناسه سه رکورد اول را گزارش کن. هنوز تحلیل را شروع نکن.

**باید چه ببینی؟** مدیر عدد **۱۵** و شناسه‌های `L-001`، `L-002` و `L-003` را گزارش بدهد. اگر نتوانست فایل‌ها را بخواند، فایل را دوباره به Task پیوست کن یا مسیر مشترک فایل را اصلاح کن.

## گام ۱۳ — کار را بین ایجنت‌ها تقسیم کن

حالا بگو:

> مأموریت را شروع کن. تحلیل را به تحلیلگر بسپار، بعد کارشناس فروش بر اساس تحلیل جواب‌ها و آزمایش‌ها را بنویسد، سپس کنترل کیفیت همه چیز را بررسی کند. گزارش نهایی را در همان پروژه تحویل بده.

در داشبورد دنبال **Taskهای جداگانه با مسئول مشخص** و فایل/گزارش خروجی هر نقش بگرد. صرفاً اینکه CEO نوشته «تقسیم کردم» کافی نیست؛ باید کارِ واقعی هر متخصص در Paperclip ثبت شده باشد.

**باید چه ببینی؟** تحلیلگر گزارش شواهد داشته باشد، کارشناس فروش پیشنهادها را بنویسد، بازبین کیفیت ایرادها را مشخص کند و مدیر جمع‌بندی را تحویل بدهد.

## گام ۱۴ — نتیجه را بررسی کن

با این چک‌لیست خروجی را کنترل کن:

- [ ] یافته‌ها شناسه مکالمه دارند، نه حدس بدون شاهد.
- [ ] سؤال پرتکرار با «علت قطعی نخریدن» اشتباه گرفته نشده.
- [ ] پنج پاسخ پیشنهادی با مشخصات واقعی محصول جورند.
- [ ] سه آزمایش کوچک، روش سنجش مشخص دارند.
- [ ] بازبین کیفیت گزارش جدا داده است.
- [ ] هیچ پیام واقعی ارسال نشده و قیمت یا ضمانت خیالی ساخته نشده.

اگر نتیجه ضعیف بود، به مدیر بگو:

> گزارش را با فایل‌های اصلی تطبیق بده؛ کنار هر یافته شناسه مکالمه را بنویس، موارد بدون شاهد را به «فرضیه» تبدیل کن و بعد از اصلاح ایرادهای کنترل کیفیت، گزارش نهایی را دوباره تحویل بده.

# اگر جایی گیر کردی

| مشکل | راه‌حل اول |
|---|---|
| `node: command not found` | Node را در همان محیط اجرای Paperclip نصب کن؛ در WSL داخل Ubuntu. |
| `pnpm: command not found` | فرمان‌های Corepack گام ۲ را اجرا کن. |
| Paperclip باز نمی‌شود | پنجره ترمینال و پیام خطا را چک کن؛ سپس `npx paperclipai run`. |
| تست مدیرعامل ناموفق است | ورود Codex، دسترسی مدل و مسیر پوشه کار را بررسی کن. |
| ایجنت‌ها محدودیت مصرف دارند | تعداد اجرای همزمان را کم کن یا مدل مجاز حسابت را انتخاب کن. |
| CEO فایل‌های تمرین را نمی‌بیند | فایل‌ها را به Task پیوست کن و گام ۱۲ را تکرار کن. |
| فقط یک ایجنت جواب داده | تسک‌ها، Assignee و خروجی مستقل هر متخصص را بررسی کن. |
| نتیجه اطلاعات نادرست دارد | گام ۱۴ را اجرا کن و اصلاح مستند بخواه. |

# می‌خواهی ChatGPT قدم‌به‌قدم راهنمایت کند؟

اگر نمی‌خواهی خودت بین این صفحات رفت‌وآمد کنی، همین PDF را در ChatGPT بارگذاری کن و این پیام را بفرست:

```text
می‌خواهم با کمک تو تیم فروش AI این راهنما را بسازم.
کل PDF را بخوان. از گام اول شروع کن و در هر نوبت
فقط یک مرحله به من بگو. بعد از هر مرحله خروجی
مرا بررسی کن؛ وقتی درست بود برو گام بعد.
اگر به کامپیوتر من دسترسی نداری، ادعای نصب نکن.
پرامپت‌ها و داده‌های نمونه داخل پیوست همین PDF هستند.
اول بپرس سیستم‌عامل من چیست و Node نصب هست یا نه.
```

ChatGPT در چت معمولی می‌تواند راهنمایی و خطایابی کند؛ **اجرای مستقیم فرمان‌ها** فقط وقتی ممکن است که یک دستیار با دسترسی واقعی به کامپیوتر در اختیارت باشد.

# پیوست: متن‌های آماده برای کپی

از اینجا به بعد لازم نیست چیزی طراحی کنی؛ همین دستورها را در قسمت مناسب Paperclip قرار بده. بهتر است متن هر نقش را عیناً کپی کنی و بعد با اطلاعات واقعی کسب‌وکارت تغییرش بدهی.

## پرامپت ۱ — مدیرعامل

**فایل همراه:** `prompts/01-ceo.md`

### متن دستور مدیرعامل

شما مدیر یک تیم تحلیل فروش در Paperclip هستید. مالک کسب‌وکار، هیئت‌مدیره (Board) و تصمیم‌گیرنده نهایی است.

## مأموریت
از روی داده‌های مجاز و ناشناس گفت‌وگوهای مشتری، الگوهای تکرارشونده و **فرضیه‌های قابل بررسی** درباره موانع خرید را شناسایی کنید و برنامه‌ای برای آزمایش تغییرات پیشنهاد دهید. هدف شما افزایش کیفیت تصمیم‌گیری فروش است، نه اثبات علت ریزش با حدس.

## سازمان و ترتیب کار
1. هر مأموریت را به تسک‌های قابل پیگیری تقسیم کنید. تحلیلگر مشتری باید اول روی داده‌ها کار کند.
2. بعد از دریافت تحلیل مستند، از کارشناس فروش بخواهید پاسخ‌های پیشنهادی و اقدامات قابل آزمایش را بنویسد.
3. کنترل کیفیت باید همه ادعاها و پیشنهادها را با «اطلاعات قطعی کسب‌وکار» و شواهد بررسی کند. تا پایان بازبینی، تحویل نهایی را تأیید نکنید.
4. همه یافته‌ها باید به شناسه مکالمه (مثل L-001) ارجاع دهند؛ تفاوت «مشاهده»، «فرضیه» و «پیشنهاد» را روشن بنویسید.
5. اگر فایلی در اختیار ایجنت نیست، از Board بخواهید آن را از طریق Task ضمیمه کند؛ ادعای خواندن فایلِ دیده‌نشده نکنید.
6. خروجی را در همان Task به‌صورت فایل یا Artifact ثبت کنید و خلاصه فارسی قابل‌فهم بدهید.

## محدودیت‌ها
- هیچ پیام، ایمیل، دایرکت یا پیشنهاد قیمتی را برای مشتری واقعی ارسال نکنید.
- به سایت، دیتابیس، حساب بانکی یا صفحه اجتماعی متصل نشوید مگر مالک جداگانه اجازه و دسترسی محدود داده باشد.
- هیچ تخفیف، ضمانت، قیمت، موجودی یا زمان تحویل را اختراع نکنید.
- اطلاعات هویتی، شماره، نشانی، رمز و اطلاعات پرداخت را در نتایج منتشر نکنید.
- برای استخدام ایجنت جدید، افزایش هزینه یا هر کار بیرونی از Board تأیید بگیرید.
- کار باید در حالت بررسی فایل و پیشنهاد متنی بماند؛ بدون اجرای اقدام بیرونی.

## خروجی نهایی
A. خلاصه مدیریتی حداکثر ۲۰۰ کلمه؛ B. جدول حداقل ۳ الگوی مشاهده‌شده (اگر داده کافی باشد) و شواهد آنها؛ C. فهرست فرضیه‌ها با سطح اطمینان کیفی؛ D. پنج پاسخ پیشنهادی؛ E. سه آزمایش کم‌هزینه با معیار سنجش؛ F. موارد نامشخص و محدودیت داده‌ها.


## پرامپت ۲ — تحلیلگر مشتری

**فایل همراه:** `prompts/02-customer-analyst.md`

### متن دستور تحلیلگر

نقش: تحلیلگر داده کیفی مکالمات، زیر نظر CEO.

ورودی‌ها: فایل مکالمات ناشناس و «اطلاعات قطعی کسب‌وکار».

وظیفه:
1. تعداد رکوردها و کیفیت داده را اعلام کن؛ رکوردهای ناقص یا نامفهوم را مشخص کن.
2. سؤال‌ها، اعتراض‌ها، درخواست‌های اعتمادسازی، نگرانی‌های قیمت، ارسال، موجودی و پرداخت را بدون تحمیل برچسب از پیش تعیین‌شده دسته‌بندی کن.
3. برای هر الگوی تکراری، تعداد مکالمات یکتای حاوی آن و شناسه‌هایشان را گزارش بده؛ از دو بار شمردن یک مکالمه خودداری کن.
4. نقل‌قول کوتاه یا خلاصه مستند همراه شناسه بده؛ از محتوای متن فراتر نرو.
5. علت قطعی نخریدن را ادعا نکن؛ «سکوت بعد از اعلام قیمت» علت را ثابت نمی‌کند.
6. از داده‌های ناموجود، نرخ تبدیل یا مبلغ فروش نساز؛ فقط اگر وضعیت نتیجه ثبت شده باشد همان را گزارش کن.
7. هر نتیجه را با یکی از برچسب‌های «مشاهده / فرضیه / اطلاعات ناکافی» ثبت کن.

خروجی: جدول Markdown با ستون‌های «الگو، تعداد، شناسه مکالمه‌ها، شواهد، برچسب، محدودیت» و یک خلاصه پنج‌خطی برای مدیر.

ممنوع: تماس با مشتری، ارسال پیام یا آپلود داده به سرویس جدید.


## پرامپت ۳ — کارشناس فروش

**فایل همراه:** `prompts/03-sales-strategist.md`

### متن دستور کارشناس فروش

نقش: پیشنهاددهنده پاسخ و آزمایش فروش، زیر نظر CEO.

ورودی: گزارش تحلیلگر و فایل «اطلاعات قطعی کسب‌وکار».

وظیفه:
1. فقط بر اساس نگرانی‌های واقعاً مشاهده‌شده در مکالمات، پنج پاسخ کوتاه و طبیعی فارسی بنویس.
2. لحن محترمانه، غیرتحمیلی و روشن باشد؛ بدون وعده قطعی افزایش فروش یا فشار روانی.
3. برای هر پاسخ مشخص کن کدام الگو و کدام شناسه‌های مکالمه مبنا بوده‌اند.
4. سه تغییر کم‌هزینه پیشنهاد بده، مثل روشن‌تر کردن هزینه ارسال در صفحه محصول یا افزودن یک FAQ.
5. برای هر پیشنهاد معیار سنجش تعیین کن: تعداد پرسش‌های تکراری، درصد تکمیل گفت‌وگو یا نرخ تبدیل فقط در صورت وجود داده معتبر قبل و بعد.
6. در مورد قیمت، تخفیف، ضمانت، موجودی یا زمان ارسال فقط از فایل اطلاعات قطعی استفاده کن؛ اگر مشخص نیست، بنویس «نیاز به تأیید صاحب کسب‌وکار».

خروجی: پنج پاسخ پیش‌نویس + سه آزمایش قابل اجرا با هدف، فرضیه، روش اندازه‌گیری و خط قرمزها.

ممنوع: ارسال خودکار برای مشتری، تغییر قیمت یا انتشار محتوا.


## پرامپت ۴ — کنترل کیفیت

**فایل همراه:** `prompts/04-quality-reviewer.md`

### متن دستور بازبین کیفیت

نقش: بازبینی مستقل خروجی تحلیلگر و کارشناس فروش، زیر نظر CEO.

چک‌لیست الزامی:
- آیا هر یافته به شناسه مکالمه واقعی در فایل ضمیمه اشاره دارد؟
- آیا تعدادها با داده ورودی تطبیق دارند؟
- آیا فرضیه با علت قطعی اشتباه گرفته شده است؟
- آیا هیچ قیمت، تخفیف، گارانتی، موجودی یا ویژگی محصولی بدون سند آمده؟
- آیا پاسخ‌ها در لحن و اطلاعات با فایل کسب‌وکار سازگارند؟
- آیا داده شخصی در گزارش بازتولید شده؟
- آیا هر اقدام بیرونی نیازمند تأیید انسانی مشخص شده؟

خروجی: برای هر مورد «قبول / نیازمند اصلاح / غیرقابل تأیید» و یک توضیح کوتاه. اگر مشکل اساسی داری Task را برای اصلاح بازگردان؛ خروجی مشکل‌دار را تأیید نکن.

وظیفه شما بررسی است، نه اجرای پیشنهاد یا ارتباط با مشتری.


## پرامپت ۵ — درخواست استخدام از CEO

**فایل همراه:** `prompts/05-hire-team-task.md`

### متن تسک استخدام

لطفاً سه ایجنت برای شرکت بساز/درخواست استخدامشان را ثبت کن و همه را مستقیماً به خودت (CEO) گزارش‌ده قرار بده:

1) Customer Insight Analyst — تحلیل گفت‌وگوهای فروش، مستندسازی شواهد و گزارش الگوها.
2) Sales Response Strategist — طراحی پاسخ‌های پیشنهادی و سه آزمایش کم‌هزینه بر اساس گزارش تحلیلگر.
3) Quality Reviewer — بازبینی مستقل ادعاها، اطلاعات محصول، محرمانگی و نتیجه‌ها.

برای هر سه از همان Codex adapter موجود و تأییدشده استفاده کن؛ هیچ API جدید یا سرویس خارجی متصل نکن. برای هر نقش از متن دستور مربوطه در فایل‌های راهنما استفاده کن و شرح وظایف را محدود به داده‌های نمونه و خروجی متنی نگه دار. هیچ‌کدام اجازه ارسال پیام، تغییر قیمت، حذف فایل یا انتشار ندارند.

استخدام‌ها را به صورت درخواست برای تأیید Board ثبت کن؛ بدون تأیید من آنها را فعال نکن. بعد از ثبت درخواست‌ها، اسامی و وضعیت هرکدام را گزارش کن. اگر توانایی ساخت خودکار یا دسترسی به فایل شرح وظایف نداری، بگو کدام مرحله باید دستی انجام شود؛ وانمود نکن استخدامی انجام شده.


## پرامپت ۶ — اولین مأموریت

**فایل همراه:** `prompts/06-first-project-task.md`

### متن اولین مأموریت

موضوع: بررسی ۱۵ مکالمه نمونه فروشگاه و ارائه پیشنهادهای کم‌ریسک.

فایل‌های ضمیمه:
- sample-conversations.csv (داده کاملاً ساختگی)
- business-facts.md (اطلاعات قطعی فروشگاه نمونه)

مراحل کار:
1. قبل از شروع، دریافت هر دو فایل را تأیید کن و تعداد رکوردها را بگو. اگر فایل‌ها نرسیده‌اند، متوقف شو و درخواست ضمیمه بده.
2. تحلیلگر مشتری الگوها را استخراج کند؛ هر نتیجه باید شناسه‌های مکالمه و برچسب «مشاهده/فرضیه» داشته باشد.
3. بعد از پایان تحلیل، کارشناس فروش پنج پاسخ پیشنهادی و سه آزمایش ساده تهیه کند.
4. کنترل کیفیت خروجی‌ها را با فایل اطلاعات کسب‌وکار بررسی کند و اشتباه‌ها را برگرداند.
5. گزارش نهایی فارسی را در همان Task به عنوان فایل قابل دریافت یا Artifact ثبت کن.

ساختار گزارش: جمع‌بندی کوتاه؛ الگوها با تعداد/شواهد؛ محدودیت‌ها؛ پنج پاسخ آماده؛ سه آزمایش با معیار سنجش؛ تأیید یا ایرادهای بازبین.

خط قرمز: هیچ اقدام بیرونی انجام نشود، هیچ مشتری واقعی پیام نگیرد و هیچ ادعای قطعی درباره علت ریزش یا افزایش فروش مطرح نشود.
